## UI/UX

Kernbefunde: kein Dunkelmodus für den Nachtdienst; 288 aus Inline-Styles
nachgebildete Hash-Klassen mit 919 `!important` in `modules.css`; Kontrastfehler
bei Feldrändern (1,28:1), grünem Text und roten Etiketten; „Ghost“-Buttons
erscheinen als Primärbuttons (14×); ungestylte Fehlerseiten; Emojis als Icons;
unterschiedliche Statusfarben in Web und App.

Umsetzung „Wachbuch Klar 2“ (Web und App gleich):

- Schrift Atkinson Hyperlegible Next (lokal, OFL) für alle Oberflächen.
- Tokens hell und Nachtdienst (System oder Schalter), Organisationsprofile mit
  Nachtvarianten, Feldränder ≥ 3:1, Etiketten mit Statuspunkt.
- Einheitliche Statusbedeutung: dringend = rot, offen = blau, in Arbeit =
  gelb, wartend = neutral, erledigt = grün.
- Kopfleiste als Fläche, Warnmarkierung als einziges Markenelement,
  SVG-Icons statt Emojis (265 → 0), Hash-Klassen 288 → 0, `!important`
  919 → 1, feste Farben in den App-Stilen → 0.
- Gestaltete Fehlerseiten, leere Zustände mit nächster Aktion, eine
  Primäraktion je Ansicht.

## Installation für jede Wache

`install.sh` richtet alles mit einem Befehl ein: Vorprüfung, `.env` mit
unabhängigen Zufallswerten, Betriebsart `local`, `lan` (Caddy mit eigener CA)
oder `domain` (Let's Encrypt), vorgefertigte Images (App, Datenbank, Backup;
amd64 und arm64), `wachbuch`-CLI für Status, Logs, Backup, Restore, Update und
Deinstallation. Entwickler bauen lokal über `compose.build.yml`.

## Ende-zu-Ende-Test auf macOS (Colima, Docker 29)

| Schritt | Ergebnis |
| --- | --- |
| `install.sh --mode lan --build` in leeren Ordner | 10 Dienste healthy nach 43 s |
| Ersteinrichtung im Browser mit Einrichtungscode | Wache und Admin angelegt |
| `wachbuch update` (zweimal) | Backup vorher, Neubau, Daten erhalten |
| Browser-Szenario über HTTPS (Playwright/Chromium) | 23/23 Prüfungen |
| App im iOS-Simulator gegen denselben Server | siehe Client-Repo, README „Ende-zu-Ende-Test“ |

Das Browser-Szenario: Einladung per Einmal-Link, Aktivierung, verbrauchter
Link liefert 410, Übergabe anlegen, Mangel mit Foto, Mitglied erhält 403 auf
Team und Einstellungen, Schichtleitung erledigt die Übergabe, Nachtdienst-Modus
bleibt nach Neuladen, Abmelden sperrt, API mit Token (me, Übergaben, paginierte
Mängel, Anlegen, 400 bei Nicht-Objekt-JSON, Widerruf → 401), keine
unerwarteten Fehlerantworten.

Dabei gefunden und behoben:

- **Kontoaktivierung im Browser unmöglich:** `Referrer-Policy: no-referrer`
  ließ Browser `Origin: null` senden, die CSRF-Prüfung lehnte ab. Der
  Django-Testclient sendet keinen Origin und hatte das nie gezeigt.
- Docker-Standardname „Wachbuch“ statt „Wachwerk“.
- Erster Backup-Dump vor den Migrationen (leer).
- Produktgrenze: Lager schlug „Einsatzverbrauch am Patienten“ vor.
