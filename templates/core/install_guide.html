{% translate "2. Welcher Rechner?" %}

{% translate "Es muss kein Raspberry Pi sein. Jeder sparsame 64-Bit-Rechner, der rund um die Uhr laufen darf, eignet sich – gebrauchte Thin Clients und Mini-PCs aus Büros sind oft die günstigste und robusteste Wahl." %}

{% translate "Tipps für gebrauchte Thin Clients und Mini-PCs" %}

  • {% translate "Gebraucht kosten sie oft nur einen zweistelligen Euro-Betrag – die Angebote schwanken stark, Preise vergleichen lohnt sich." %}
  • {% translate "Sie kommen häufig mit sehr kleinem Flash-Speicher (8–32 GB) und 4 GB RAM. Eine M.2-SSD (SATA oder NVMe – je nach Gerät) und gegebenenfalls einen RAM-Riegel einplanen." %}
  • {% translate "Vor dem Kauf prüfen: 64 Bit, welcher M.2-Typ und welche Länge passt, wie viele RAM-Steckplätze, Netzteil dabei." %}
  • {% translate "Im BIOS „Nach Stromausfall einschalten“ (AC Power Recovery) aktivieren, damit der Server nach einem Stromausfall von selbst wieder startet." %}
  • {% translate "Als Betriebssystem Debian oder Ubuntu Server (LTS, 64 Bit) installieren, danach Docker." %}
  • {% translate "Das Komplett-Skript für eigenes WLAN und Touch-Terminal gibt es bisher nur für den Raspberry Pi. Auf anderen Rechnern mit dem Installer im Modus „lan“ installieren, das WLAN über einen eigenen Access Point bereitstellen und für das Touch-Terminal in der Datei .env „TERMINAL_ENABLED=true“ setzen und am Touch-Monitor die Terminal-Seite im Browser-Vollbild öffnen." %}

{% translate "3. In fünf Schritten startklar" %}

  1. {% translate "Rechner vorbereiten" %}

    {% translate "Docker installieren (Anleitung auf docs.docker.com). Für den Internet-Weg vorher beim Domain-Anbieter einen A-Eintrag auf die IP-Adresse des Servers anlegen, z. B. wache.example.org." %}

    {% translate "Für den Raspberry Pi in der Wache gibt es ein eigenes Skript, das zusätzlich WLAN, Zertifikat und Touch-Terminal einrichtet – siehe „Raspberry Pi“ weiter unten." %}

  2. {% translate "Installer starten" %}

    {% translate "Im Terminal des Rechners eingeben. Wer das Skript vorher lesen möchte, lädt es zuerst herunter:" %}

    curl -fsSLO https://raw.githubusercontent.com/Katschko-IT/Rettungswache-Wachbuch/main/install.sh
less install.sh
sudo sh install.sh

  3. {% translate "Fragen des Installers beantworten" %}

    {% translate "Name der Wache und Betriebsart: „local“ (nur dieser Rechner), „lan“ (im Netz der Wache) oder „domain“ (im Internet mit eigener Domain). Der Installer prüft alles, erzeugt sämtliche Schlüssel und zeigt am Ende die Adresse und den Einrichtungscode." %}

  4. {% translate "Wache einrichten" %}

    {% translate "Die angezeigte Adresse im Browser öffnen, den Einrichtungscode eingeben und dem Assistenten folgen: Name und Anschrift, eigenes Admin-Konto, Impressum und Datenschutz, Zwei-Faktor-Anmeldung, Module." %}

  5. {% translate "Team einladen und absichern" %}

    {% translate "Kolleginnen und Kollegen per Einladungslink oder QR-Code einladen. Die Datei .env im Installationsordner auf den USB-Stick kopieren und sicher verwahren – ohne sie sind Datenbank und Backups nicht mehr lesbar. Dann automatische Updates einschalten:" %}

    sudo /opt/wachbuch/wachbuch auto-update an

{% translate "Raspberry Pi in der Wache" %}

{% translate "Raspberry Pi OS (64 Bit, mit Desktop) auf die SSD schreiben, den Pi einmal per Kabel ans Internet hängen und dann:" %}

git clone https://github.com/Katschko-IT/Rettungswache-Wachbuch.git
cd Rettungswache-Wachbuch
sudo WLAN_SSID="Wachwerk RW1" deploy/pi/setup-pi.sh
sudo reboot

{% translate "Nach dem Neustart öffnet der Touch-Bildschirm direkt die Ersteinrichtung. Das Skript spannt ein eigenes WLAN auf, erzeugt ein Zertifikat und zeigt den Einrichtungscode an. Ausführlich mit Abhak-Liste:" %} docs/PI-WACHENTERMINAL.md

{% translate "Im Alltag" %}

{% translate "Verwaltet wird mit dem Programm „wachbuch“ im Installationsordner. Unter Linux mit sudo und vollem Pfad wie unten, unter macOS ohne sudo als ~/wachbuch/wachbuch:" %}

sudo /opt/wachbuch/wachbuch status{% translate "Läuft alles?" %}
sudo /opt/wachbuch/wachbuch update{% translate "Neue Version holen – vorher wird automatisch gesichert." %}
sudo /opt/wachbuch/wachbuch backup{% translate "Sofort ein Backup anlegen." %}
sudo /opt/wachbuch/wachbuch restore DATEI{% translate "Ein Backup wiederherstellen (mit Rückfrage)." %}
sudo /opt/wachbuch/wachbuch setup-code{% translate "Den Einrichtungscode noch einmal anzeigen." %}

{% translate "Wenn etwas hakt" %}

{% translate "Der Browser warnt vor dem Zertifikat (Betriebsart „lan“)." %}

{% translate "Im Wachen-Netz stellt Wachwerk ein eigenes Zertifikat aus. Das Stammzertifikat einmal auf jedem Gerät als vertrauenswürdig installieren. Der Installer zeigt den Befehl, mit dem du die Datei wachbuch-ca.crt erhältst." %}

{% translate "Ich habe den Einrichtungscode nicht mehr." %}

{% translate "„sudo /opt/wachbuch/wachbuch setup-code“ ausführen (macOS: ~/wachbuch/wachbuch setup-code). Nach abgeschlossener Einrichtung gibt es keinen Code mehr – dann ist das auch richtig so." %}

{% translate "Der Installer meldet einen belegten Port." %}

{% translate "Ein anderes Programm nutzt den Port bereits, oft ein Webserver. Entweder das Programm beenden oder den Installer mit einem anderen Port starten, z. B. „sudo sh install.sh --port 8091“." %}

{% translate "Let’s Encrypt stellt kein Zertifikat aus." %}

{% translate "Meist zeigt der DNS-Eintrag noch nicht auf den Server oder die Ports 80 und 443 sind in der Firewall geschlossen. DNS-Änderungen brauchen manchmal einige Minuten." %}

{% translate "Was passiert, wenn der Rechner kaputtgeht?" %}

{% translate "Wachwerk auf neuer Hardware installieren, die gesicherte .env zurückkopieren und das letzte Backup wiederherstellen. Darum gehören .env und Backups auf einen Stick außerhalb des Rechners." %}
